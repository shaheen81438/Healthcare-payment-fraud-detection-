# Data Dictionary

Provenance legend — **[R]** real public CMS/OIG data · **[S]** synthetic, generated by this
project · **[A]** authored reference data (documented assumptions).

## 1. `raw.cms_provider_service` — [R] CMS Medicare Physician & Other Practitioners (by Provider and Service)

Committed calibration snapshot: 480 rows / 12 specialties (metadata in
`data/reference/cms_snapshot_metadata.json`); full pulls via `src/data/ingest_cms.py`.
Provider-level annual aggregates — contains **no beneficiary-level data**. Provider names and
addresses are dropped at ingestion; NPIs are used only for aggregate benchmarks and are never
scored or displayed as risky.

| Column | Type | Description |
|---|---|---|
| npi | text | Rendering provider NPI (public) |
| provider_type | text | CMS provider specialty (e.g., Cardiology) |
| state | text | Practice state |
| ruca | text | Rural-urban commuting area code |
| hcpcs | text | HCPCS/CPT code billed |
| hcpcs_desc | text | CMS-published code description |
| drug_ind | text | Y if drug HCPCS |
| place_of_service | text | F (facility) / O (office) |
| total_benes | numeric | Distinct beneficiaries for this provider-code |
| total_services | numeric | Service count |
| total_bene_day_services | numeric | Distinct bene-days |
| avg_submitted / avg_allowed / avg_paid | numeric | Average charge / Medicare-allowed / Medicare-paid amounts |

## 2. `raw.leie_exclusions` — [R] OIG LEIE (loader) / [S] fixture

`npi`, `exclusion_type` (statutory authority, e.g. `1128a1`), `exclusion_date`, `specialty`,
`state`, `fraud_related` (derived flag for fraud-conviction authorities). The committed test
fixture uses reserved fake NPIs (`999000xxxx`) — it contains **no real exclusion records**.

## 3. `ref.*` — [A] authored reference tables

| Table | Contents | Provenance note |
|---|---|---|
| pos_codes | CMS place-of-service code set (subset) | Real public code meanings |
| dx_groups | 24 synthetic diagnosis groups with typical specialties | Authored; stands in for CCS/CCSR-style grouping |
| dx_procedure_compat | Compatibility weight (0–1) per service category × dx group | Authored clinical-plausibility matrix |
| ptp_pairs | Illustrative NCCI-style procedure-to-procedure edit pairs | **Illustrative**, modeled on NCCI PTP structure; production would load the CMS NCCI file |
| em_levels | E/M code families, levels, relative payments | Real code families; relative payments approximate |

## 4. `staging.claims` — [S] synthetic claim lines (the scored population)

Generated by `src/data/synthetic/` calibrated to the real snapshot; raw form
(`data/raw/claims_raw.csv.gz`) additionally carries injected data-quality defects.

| Column | Type | Description | Available pre-payment? |
|---|---|---|---|
| claim_id | text (CLM-########) | Unique claim line ID | yes |
| bene_id | text (BEN-######) | Synthetic beneficiary | yes |
| provider_id | text (PRV-#####) | Synthetic billing provider | yes |
| specialty | text | Provider specialty (denormalized) | yes |
| hcpcs | text | Procedure code (real code vocabulary) | yes |
| modifier | text | '', 25, 59, LT, RT | yes |
| units | int | Service units | yes |
| dx_group | text | Diagnosis group (DXG01–24) | yes |
| pos | text | Place-of-service code (UNK if missing at intake) | yes |
| service_date / service_end_date | date | Service period | yes |
| submit_date | date | Claim submission date | yes |
| submitted_amount | numeric | Billed charge | yes |
| allowed_amount | numeric | Contractual allowed amount | yes |
| paid_amount | numeric | Amount paid | **post-pay only** (this platform scores post-payment) |

`staging.providers` (provider_id, specialty, state) and `staging.beneficiaries`
(bene_id, age_band, sex, state) are synthetic dimensions. No names, addresses, or real
identifiers exist anywhere in the synthetic population.

## 5. `labels.claim_labels` — [S] generated supervision (kept out of feature space)

| Column | Type | Description |
|---|---|---|
| claim_id | text | FK to claims |
| is_improper | bool | True if any FWA pattern was injected into this claim |
| patterns | text | Semicolon-joined pattern IDs (F01–F12); '' if none |
| improper_amount | numeric | Ground-truth injected improper payment, capped at paid_amount |

Labels exist for every generated claim (including rows later quarantined by validation); they are
joined to features **only** at training/evaluation time. See `docs/labeling.md` for every
assumption.

## 6. Pipeline artifacts

| Location | Contents |
|---|---|
| `data/raw/claims_raw.csv.gz` | Defected raw claims — the pipeline's input |
| `data/interim/quarantine.parquet` | Rows failing error-severity validation, with reasons |
| `data/interim/ground_truth_claims.parquet` | Pre-defect claims (QA/leakage tests only — not a pipeline input) |
| `data/processed/*.parquet` | Clean claims, labels, providers, beneficiaries |
| `monitoring/reports/validation_report.json` | Per-check validation results (V001–V010) |
| `meta.dataset_versions` | Dataset version hash, row counts, positive rate per build |
