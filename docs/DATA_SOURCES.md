# MedIntegrity AI Data Sources

## CMS provider-service data

The CMS Medicare Physician & Other Practitioners provider-service dataset is a
provider-level aggregate source used for peer benchmarks and synthetic-data
calibration:

<https://data.cms.gov/provider-summary-by-type-of-service/medicare-physician-other-practitioners/medicare-physician-other-practitioners-by-provider-and-service>

The committed snapshot and retrieval metadata are in
`data/reference/cms_snapshot_metadata.json`. These rows are not adjudicated
claim lines and do not provide claim-level fraud labels.

## OIG LEIE

The official List of Excluded Individuals/Entities is loaded by
`src/data/ingest_leie.py`:

<https://oig.hhs.gov/exclusions/exclusions_list.asp>

The repository contains a synthetic fixture for tests and offline demos. An
official download can be supplied at runtime. NPI matching is preferred; fuzzy
name matching is secondary and always requires manual verification.

## Synthetic claims

Claim-level development data is generated by `src/data/synthetic/` and calibrated
to the CMS aggregate snapshot. Labels are injected synthetic pattern labels and
are kept separate from model features. They are not CMS outcomes, CERT labels,
or evidence of real fraud.

No PHI, SSNs, credentials, or confidential records should be committed.

## Local artifact provenance

`src/data/provenance.py` provides `file_provenance()` for an existing local
artifact and `record_dataset_provenance()` for successful ingestions. The
metadata-only JSON manifest at `monitoring/reports/data_provenance.json` records
source, identifier or URL, time, filename, format, row and column counts,
classification, and validation status. It does not record row values or column
names. Missing files raise `FileNotFoundError`; an ingestion record is written
only after the loader or validated dataset build succeeds. CMS snapshot retrieval
details also remain in `data/reference/cms_snapshot_metadata.json`.
