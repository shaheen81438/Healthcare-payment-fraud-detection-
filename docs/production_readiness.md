## Environment caveats recorded during the build

- Container-image pulls were blocked in the build sandbox, so `docker build` and
  `docker compose --profile serve` are verified **by CI definition** (the GitHub Actions `docker`
  job builds both targets and health-smokes the API) rather than by a local run in that sandbox.
  The Dockerfiles/compose files are conventional; run `make compose-serve` locally to confirm.
- MLflow ran as a native server (same backend semantics as the compose service) during the build;
  the compose `mlflow` service pin matches the client version range.
